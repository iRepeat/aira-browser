# 同步期间的主线程响应性

2026-09-19

本次修复覆盖自动和手动同步共用的节流器，以及华为历史同步的 TaskPool 数据传递。没有改变 Provider 选择、云端协议、合并与删除规则、持久化格式或冷启动任务时序。

## 可重复证据

执行 `node scripts/check-aira-sync-responsiveness.cjs`，直接加载生产 ArkTS 节流器、传输编解码器和计算执行器；用受控时钟与编码成本检查连续占用时间。测试不访问设备、账号或用户数据，数值是模拟工作成本，不是真机耗时或 FPS。

修复前，7 条、每条 10 ms 的同步小批次可以连续运行 70 ms；250 条、每条 1 ms 的批次最长连续运行 201 ms。原因是默认预算为 200 ms，而且只有到预算/计数阈值才查看滑动信号。仅 `await` 一个已经完成的 Promise 不会给输入事件一个新的事件循环回合。

第二组用 512 条合成历史记录经过实际计算执行器。TaskPool 发送前整份 JSON 编码、结果返回后整份解码分别触发 105.5 ms / 135.5 ms 的模拟连续占用。原来的阶段结束让步发生在整块工作之后。

## 修改

- 共用节流器以 8 ms 为连续工作目标，在记录之间检查新发生的滑动。单条操作仍然不可抢占，因此这不是单帧耗时的硬保证。
- 计算批次使用 `setTimeout(..., 0)` 让出事件循环，不为每个短计算片固定增加 16 ms 等待；阶段和写入边界保留原来的等待。滑动期间的等待仍有 4 秒上限，上限之后允许一个计算片，避免每条记录重新等待。
- 历史数据的 UTF-8 大小预估、物理行编码/解码和复制都能在批次中让步。大 buffer 的复制按 64 KiB 切片。
- 历史逻辑状态使用进程内的逐记录 JSON 帧，主线程可以在编码或解析记录之间让步；工作线程使用相同格式的同步编解码。物理行的既有二进制布局保持兼容。该逻辑状态格式只供当前进程 TaskPool 传递，既不持久化也不发送到服务端。
- 保留 TaskPool 低优先级、普通解码/合并/写入路径的 24 MiB 保护及协作回退。2026-09-19 真机复现后修正副本 lite 路径：不再仅因超过 24 MiB 拒绝任务并转而执行同样大小的全量副本任务；实际任务失败仍回退。

## 验证边界

回归覆盖小批次、整批次、中途开始滑动、持续滑动的有界进度、工作线程收发、预估扫描、无变化合并、Unicode、访问记录、删除记录、删除范围、清空边界、保留边界、空状态、截断数据和物理行布局兼容。构建脚本会执行此回归。

9 项响应性回归和构建前的架构/同步契约检查全部通过。常规 Community 构建因缺少匹配签名配置停止；使用仓库已有的 `AIRA_DISTRIBUTION=community AIRA_ALLOW_UNSIGNED_BUILD=1 SKIP_INSTALL=1 ./scripts/build-aira-browser.sh` 完成 ArkTS 编译与免签名 HAP 打包。未安装或进行真机帧率测试。

这些检查证明明确的连续工作问题被修正，不能证明整轮同步或实际网页滚动已无卡顿。单条特别大的记录、ArkData 查询/事务、工作线程返回的其他对象和其他同步域的独立计算仍可能占用时间；改善幅度需要低端真机帧轨迹确认。

平台依据：本机 Huawei DevEco SDK `@ohos.taskpool.d.ts` 将 TaskPool 定义为多线程运行环境，并支持 LOW 优先级；华为[Web 帧率问题分析](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/web-frame-rate-analysis)要求结合 ArkWeb、Frame、ArkUI、Time 轨迹分析。8 ms、64 KiB 和上述切片方式是 Aira 工程选择，并非华为保证值。

本次没有新增平台 API 或需要更新 HarmonyOS 技能的原生平台结论。

后续真机复现、缓存空跑优化、收尾规范化分片及对应回归见 [同步卡顿复现日志](aira-sync-diagnostics.md#2026-09-19-手动复现与后续自动轮次)。

## 2026-09-19：普通历史增量的读取与计算合并到工作线程

旧路径即使已经将合并放在 TaskPool，仍在主线程读取约 14 MB 物理行、编码物理副本、读取整份历史、再编码逻辑状态。普通本地变动且云端 Head 未变时，现在只向 LOW 优先级任务传 Context、数据库名称、账号/设备标识和时间边界。任务自己读取并生成差异，消除这一路径的主线程全量 row/state pack。保留原 repair/full merge 作为损坏、不完整、保留边界变化等异常情况的回退。

为保证确认语义，任务将本次 desired state 预留为 ArrayBuffer；主线程正常确认只读 Head，不解析预留内容，Head 不一致才进入完整确认。没有把全量 desired 对象作为工作线程返回值。同步成功只清理读取前捕获的 mutation ID，同步过程中新增的变动仍留在 outbox；Provider 迁移不清理。读库映射由主线程数据库 owner 与 worker 共享，避免持久化字段解释分叉。

回归先确认旧路径会在调用线程整份读历史，再验证新路径零主线程历史读取、无输入大 buffer。真实 codec + 模拟 ArkData 边界验证账号/设备隔离、删除 roundtrip、延迟期间新增 mutation 的保留、损坏和容量边界、句柄关闭，以及 deferred confirmation 的成功/失败分支。此测试不能代替实际滚动帧轨迹验收。
