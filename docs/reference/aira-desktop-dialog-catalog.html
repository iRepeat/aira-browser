0宽度算法 唯一公式 · 4 个档位

下面 94 张卡片的宽度全部是按这个公式算出来的，不是随手给的。档位由内容形状决定，不由宽度反推——调用方只声明档位，数值由 `core` 侧解析。

公式

edge    = 24
usableW = W - edge * 2
w       = tier.width              // 档位标准宽
if W < 600: w = usableW          // 窄窗 → 全宽对话框
w       = clamp(w, tier.minWidth, usableW)
h       = min(contentHeight, tier.maxHeight, usableW... )

高度不设档位，由内容决定，只封顶 min(720vp, H - 48vp)；超过时只有正文区滚动。

禁止：百分比宽度（如 '82%'）与调用点写法宽度数字。

平台陷阱：@CustomDialog + customStyle: false 的容器默认上限是 400vp，而全仓 0 个 controller 设了 width。所以实现时必须在 controller 上写 width: tier.width，光给内容挂 maxWidth 是无效的。

动作排布规则（含防折行）

  1. 1–2 个动作 → 并排等宽（flex:1），间距 12vp。
  2. ≥ 3 个动作 → 竖向堆叠全宽。
  3. 防折行（新增）：任一标签按 14fp 估算后超过「可用宽度 / 按钮数」时，也改竖排。
    例：XS 360 档内容宽 312vp，两个按钮各 150vp；“继续使用本地功能” 8 字 × 14fp ≈ 112vp + 左右内边距 40vp = 152vp > 150vp → 会折行 → 必须竖排。
  4. 按钮标签永不折行（maxLines: 1）。宁可竖排，不缩字号。

密度决策：为什么一个数都不缩

  • 按钮 40vp 不动。这就是 HarmonyOS 平台自己在 PC/2in1 上的对话框尺寸（官方：电脑设备键鼠热区 ≥ 5mm；系统推荐触屏点击热区 40vp×40vp）。跟着平台走，才不会在系统对话框旁边显得突兀；PC/2in1 本身也可能两用触屏。
  • 标题 19fp 不动。它不是“大”—— Windows 11 对话框标题约 20px、HarmonyOS 对话框标题默认 20fp Bold。缩小反而发虚。
  • 圆角 24vp 不动。它是这套参考图语言的签名特征，缩了就不像了。
  • 内边距 24vp 不动。Material 与 Fluent 的对话框也正好都是 24。
  • 只动排布，不动尺寸。你之前看到的“仅使用期间允许”折行，根因是 3 个按钮并排，不是字号大——已经由“≥3 个竖排”修好了；叠加防折行规则后，任何档位都不会再折行。

7说明 · 同意 · 引导类弹窗（上一版漏掉的一整类）补全
